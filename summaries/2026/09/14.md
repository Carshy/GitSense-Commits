### Patterns and Recurring Elements:

*   **Drizzle ORM Adoption:** All changes consistently utilize Drizzle ORM for schema definition, leveraging its `pgTable`, column types (e.g., `uuid`, `varchar`, `integer`, `timestamp`), and constraint features.
*   **UUID Primary Keys:** A common pattern across all new tables is the use of `uuid("id").defaultRandom().primaryKey()` for unique identifiers.
*   **Timestamps:** Most tables include `createdAt` and `updatedAt` fields, typically defaulting to the current timestamp (`defaultNow()`), indicating a standard approach to auditing record creation and modification times.
*   **Foreign Key Constraints with `onDelete`:** Referential integrity is rigorously maintained through `.references()` clauses, with `onDelete` actions configured (`cascade`, `restrict`, `set null`) to manage linked record deletion behavior.
*   **Extensive Use of Indexes:** Indexes are systematically applied to foreign keys and frequently queried columns (e.g., status, timestamps) to optimize database query performance.
*   **Data Validation via `check` Constraints:** There's a strong emphasis on data integrity, with numerous `check` constraints added using `drizzle-orm`'s `sql` helper. These checks enforce rules like non-negative quantities/amounts, positive size values, non-zero changes, and ensuring a record has exactly one owner (e.g., user or guest).
*   **Custom Enums:** Several PostgreSQL enums (`fragrance_concentration`, `variant_status`, `inventory_transaction_type`, `cart_status`, `checkout_status`) are defined, promoting strong typing and constrained values for specific fields.
*   **Modular Relations Definitions:** A clear pattern emerges where relation definitions are separated into dedicated files (e.g., `catalog-relations.ts`, `cart-relations.ts`, `checkout-relations.ts`), enhancing code organization and readability.
*   **Centralized Exports:** The `index.ts` file is consistently updated to re-export all new schema and relations files, creating a single entry point for schema imports.
