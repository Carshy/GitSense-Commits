# Activity Summary for 9/12/2026

## 10:48:12 AM
The project "Nuraya-Fragrance" saw significant initial development focusing on establishing a robust backend architecture and data model, primarily between September 3rd and September 7th, 2026.

**Overall Project Setup and Tooling:**
On September 3rd, the project began with a `setup-project.sh` script to create a detailed directory structure following a domain-driven design (DDD) pattern, including modules for `auth`, `users`, `catalog`, `inventory`, etc., each with `domain`, `application`, `infrastructure`, and `presentation` layers. Initial configuration files for TypeScript (`tsconfig.json`), Prettier (`.prettierrc`, `.prettierignore`), and `package.json` were set up. `tsconfig.json` was updated to include stricter rules like `noUnusedLocals` and `noUnusedParameters`. The `package.json` was later expanded to include Drizzle ORM scripts and dependencies for database management, logging, and security.

**Core Utilities and Libraries:**
Utility files were introduced early on for error handling and security:
*   `src/lib/errors/app-error.ts` (September 3rd): Defined a custom `AppError` class with a `statusCode`.
*   `src/lib/logger/index.ts` (September 3rd): Implemented a `pino` logger with environment-dependent log levels.
*   `src/lib/security/hash.ts` (September 3rd): Provided `bcryptjs` functions for password hashing and verification.
*   `src/lib/errors/error-codes.ts` (September 3rd): Established a set of standardized `ERROR_CODES`.

**Database and Drizzle ORM Setup:**
Drizzle ORM was a central focus of the development:
*   `drizzle.config.ts` (September 3rd): Configured Drizzle for PostgreSQL, pointing to schema and migration directories, and later integrating with `DATABASE_URL` from environment variables.
*   `src/db/index.ts` (September 3rd): Initialized the Drizzle client connecting to a PostgreSQL database.
*   `src/db/schema/helpers.ts` (September 4th): A helper was created to enforce `createdAt` and `updatedAt` timestamps, and `deletedAt` for soft deletes across many schemas.

**Schema Definitions and Evolutions:**
A comprehensive database schema was progressively defined across multiple files, with many schemas adopting `uuid` primary keys, `pgEnum` for controlled values, and `timestamp` columns:

*   **User and Authorization (September 4th-5th):**
    *   `users.schema.ts`: Defined the `users` table with `email`, `phone`, `passwordHash`, and a `userStatusEnum`. Indexes were added for `email`, `phone`, and `status`. Later (September 7th), an `isVisible` boolean column was added with a default of `false`.
    *   `roles.schema.ts`: Created `roles` table with `name` (unique) and `description`, including an index on `name`.
    *   `permissions.schema.ts`: Created `permissions` table with `code` (unique) and `description`, including an index on `code`.
    *   `user-roles.schema.ts`: A join table linking `users` and `roles`, with composite primary key and indexes on `userId` and `roleId`.
    *   `role-permissions.schema.ts`: A join table linking `roles` and `permissions`, with composite primary key and indexes on `roleId` and `permissionId`.
    *   `sessions.schema.ts`: Defined `sessions` for user authentication, with `userId` (FK), `tokenHash` (unique), `expiresAt`, and `ipAddress`, adding indexes for `tokenHash` and `userId`.

*   **Customer Management (September 5th):**
    *   `customer-profiles.schema.ts`: Defined `customerProfiles` linked to `users`, including `firstName`, `lastName`, `dateOfBirth`, and marketing opt-in fields.
    *   `addresses.schema.ts`: Created `addresses` table linked to `customerProfiles`, defining an `addressTypeEnum` and common address fields.
    *   `guest-checkout-sessions.schema.ts`: Schema for tracking guest checkouts, including `sessionToken` and an optional `convertedUserId` (FK to `users`).

*   **Audit Logging (September 5th):**
    *   `audit-logs.schema.ts`: Defined a robust `auditLogs` table to track user actions, entity changes, IP addresses, and user agents, with multiple indexes for efficient querying.

*   **Catalog and Inventory (September 5th-7th):**
    *   `brands.schema.ts`: Created `brands` table with `name` (unique) and `slug` (unique).
    *   `categories.schema.ts`: Created `categories` table with `name` (unique), `slug` (unique), and a self-referencing `parentId` for hierarchical structures.
    *   `products.schema.ts`: Defined `products` linked to `brands` and `categories`, including `name`, `slug` (unique), `description`, `productStatusEnum`, and SEO fields. This schema saw several iterations, initially adding and then removing an `isVisible` field from the enum, before finally adding it as a dedicated boolean column on September 7th.
    *   `product-variants.schema.ts`: Defined `productVariants` linked to `products`, including `sku` (unique), `sizeValue`, `concentrationEnum`, and `variantStatusEnum`.
    *   `inventory.schema.ts`: Defined `inventory` for product variants, tracking `quantity` and `reservedQuantity`.
    *   `pricing.schema.ts`: Defined `pricing` for product variants, including `currency`, `amount`, and `activeFrom`/`activeUntil` dates.
    *   `product-images.schema.ts`: Defined `productImages` linked to `products`, storing `url`, `altText`, and `isPrimary` status.
    *   `fragrance-notes.schema.ts`: Created `fragranceNotes` with `name` (unique) and `slug` (unique).
    *   `product-notes.schema.ts`: A join table linking `products` and `fragranceNotes`, categorizing notes by `noteTypeEnum` (`TOP`, `MIDDLE`, `BASE`).
    *   `inventory-transactions.schema.ts` (September 7th): Introduced `inventoryTransactions` to log changes in inventory, with `inventoryId` (FK), `inventoryTransactionTypeEnum`, `quantityChange`, `reason`, and `performedBy` (FK to `users`).

**Relationships:**
Dedicated relation files (`relations.ts`, `customer-relations.ts`, `audit-relations.ts`, `catalog-relations.ts`) were used to define Drizzle ORM relationships between the various schemas, enabling complex data fetching. These files were continuously updated as new schemas were introduced, reflecting user-role, user-session, customer-address, audit-user, product-brand, product-category, product-variant-inventory, and inventory-transaction relationships.

**Front-end Development:**
*   `src/app/page.tsx` (September 7th): The initial Next.js home page was created, displaying a welcome message and basic styling, with an `Image` import later removed as it was unused.

**Key Patterns:**
*   **Modular Drizzle Schemas:** The database schema is highly modular, with each entity and its relationships defined in separate files, following Drizzle ORM's best practices.
*   **Comprehensive Data Modeling:** The changes show a detailed approach to modeling core e-commerce entities: users, roles, permissions, customers, addresses, guest checkouts, a full product catalog (brands, categories, products, variants, images, fragrance notes), inventory, pricing, and audit logs.
*   **Enums and UUIDs:** Consistent use of `pgEnum` for type safety and `uuid` for primary keys.
*   **Indexing for Performance:** Frequent addition of database indexes to critical fields for improved query performance.
*   **Timestamping and Soft Deletes:** Almost all main tables include `createdAt`, `updatedAt`, and `deletedAt` for robust record keeping and soft deletion capabilities.
*   **Clear Separation of Concerns:** Database schemas, relations, environment configuration, and utility functions are logically separated into distinct files and directories.
