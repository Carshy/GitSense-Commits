### Patterns and Recurring Elements:

*   **Modular Schema Definition**: A consistent pattern of creating individual schema files (`*.schema.ts`) for each database table and separate `*-relations.ts` files to define Drizzle ORM relationships between them.
*   **UUID Primary Keys**: All new tables uniformly use `uuid("id").defaultRandom().primaryKey()` for their primary keys.
*   **Timestamping**: `createdAt` and `updatedAt` columns with `defaultNow().notNull()` are present in almost every table, indicating robust record lifecycle tracking. Some tables also include `expiresAt` or `deletedAt`.
*   **Enum-Driven Statuses**: Extensive use of `pgEnum` for status and type fields (e.g., `cartStatusEnum`, `orderStatusEnum`, `paymentStatusEnum`), promoting data consistency and readability.
*   **Data Integrity with Check Constraints**: Frequent application of SQL `check` constraints (`sql`${table.column} > 0``) to enforce business rules, such as positive quantities, non-negative monetary values, and complex logical conditions like requiring exactly one owner (user or guest) for carts and checkout sessions. The `import { sql } from "drizzle-orm";` statement often precedes these additions.
*   **Indexing for Performance**: Regular addition of `index` and `uniqueIndex` definitions on foreign keys and critical columns (`sku`, `orderNumber`, `idempotencyKey`, active user/guest carts) to optimize database query performance and enforce uniqueness.
*   **Centralized Schema Export**: The `src/db/schema/index.ts` file is consistently updated to export new schema and relations files, serving as a single entry point for the entire database schema.
*   **E-commerce Workflow Progression**: The changes demonstrate a logical progression in building out core e-commerce functionalities: starting from catalog/product variants, moving to inventory and pricing, then to shopping carts, checkout processes, order management, and finally, a detailed payment system.
